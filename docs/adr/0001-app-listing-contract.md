# ADR 0001 — 앱 매물 API와 DTO

- 상태 **채택**
- 날짜 **2026-11-25**

## 배경

매물 컨트롤러가 같은 메서드에서 `/api`와 `/api/v1`을 받았습니다. 두 형식의 필드명과 가격 단위가 달라서 URL에 따라 JSON을 읽고 만드는 분기가 있었습니다. 앱은 만원 단위를 보내고, DB와 기존 v1 API는 원 단위를 사용합니다.

## 결정

공개 앱 API는 `/api`의 경로와 JSON을 기준으로 삼습니다. 매물 생성·상세·검색·내 매물부터 Java record 요청·응답 DTO를 도입합니다. 컨트롤러는 Spring MVC의 요청 바인딩과 `@Valid`를 사용하고 명령·조회 서비스에 위임합니다. 금액 단위 변환은 매핑 계층에서 하고 소유권은 서비스에서 확인합니다.

매물 생성 요청은 해당 DTO에만 적용되는 메시지 변환기에서 기존 OpenAPI 규칙과 엄격한 JSON 파서를 거칩니다. 이 규칙은 날짜 형식, 알 수 없는 항목, 중복 키, 누락된 좌표의 오류 응답을 결정합니다. 매물 등록의 멱등성 키·경로와 저장된 응답을 계속 사용합니다.

1차 적용에서 기존 v1 매물 호출을 별도 컨트롤러로 분리했습니다. 후속 통합에서 수정·공개·삭제를 `/api/listings`로 옮기고 ETag 규칙을 유지했습니다. 수정에 쓰는 금액은 앱과 같은 만원 단위입니다. 워커는 별도 내부 계약 `/api/v1/internal/ai-jobs`를 사용합니다.

## 결과

공개 API는 `/api` 계약에 추가합니다. 기존 v1 공개 경로에서 옮겨온 기능은 [README](../../README.md)와 OpenAPI에서 확인합니다. 외부 연동의 배포는 소비자 경로 전환과 함께 진행합니다.
