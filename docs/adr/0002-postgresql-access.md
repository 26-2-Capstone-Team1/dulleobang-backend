# ADR 0002 — PostgreSQL 검색과 데이터 접근

- 상태 **채택**
- 날짜 **2026-11-25**

## 배경

매물과 IKEA 가구 카탈로그를 전부 읽은 뒤 Java에서 조건을 적용했습니다. 사용자 저장소는 `UserEntity`와 Spring Data JPA로 기본 조회·저장을 처리하고, 다른 저장소는 JdbcTemplate에서 PostgreSQL 배열, JSONB, 행 잠금과 같은 기능을 직접 사용합니다.

## 결정

매물의 공개 상태·소유권·주소·가격·면적·지도 범위·옵션 조건과 정렬을 SQL에 적용합니다. 카탈로그의 분류·이름·상품번호 검색도 SQL로 처리합니다. 검색어와 조건은 파라미터로 바인딩합니다.

커서가 있는 목록은 DB가 돌려준 정렬된 ID로 스냅샷을 유지하고, 현재 페이지에 해당하는 레코드만 읽습니다. 다음 페이지에서 새 항목을 끼워 넣지 않고, 삭제되었거나 필터에 더 이상 맞지 않는 항목은 건너뜁니다. 앱의 매물 목록에서 `limit`과 `cursor`를 둘 다 생략하면 기존 계약대로 검색 조건에 맞는 전체 목록을 반환합니다.

사용자 데이터의 기본 CRUD는 JPA를 유지합니다. 매물, 가구, 공간, AI 작업 등의 기존 SQL 저장소는 JdbcTemplate을 사용합니다. 두 방식은 같은 데이터 소스와 Spring 트랜잭션을 사용하고, 테이블은 Flyway에서 관리합니다. 각 테이블의 쓰기 책임은 기존 저장소에 둡니다.

## 결과

페이지 단위 요청은 전체 레코드와 연관 데이터를 읽는 대신 일치하는 ID와 페이지에 해당하는 레코드를 읽습니다. 커서 형태와 일관성을 유지하기 위해 초기 조회와 후속 조회에서 조건을 만족하는 ID 집합을 구성하는 비용이 남습니다.
